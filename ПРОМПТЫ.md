## Шаг 2 — Шаблоны: загрузка .docx и разметка полей

```
В рамках того же приложения.

Задача: раздел Шаблоны — загрузка договора в .docx и разметка мест подстановки.

Сделай:
1. Миграцию для таблицы templates и приватный бакет templates в Storage.
2. Раздел Шаблоны: список загруженных шаблонов с названием, категорией и датой.
3. Загрузка .docx: файл сохраняется в Storage как есть (он понадобится для рендеринга
   с сохранением оформления), а его текст извлекается через mammoth и разбирается
   на структуру блоков по правилам из CLAUDE.md, раздел 2.1.
   Определяй тип блока по содержимому: строка капслоком по центру — title, строка вида
   "1. НАЗВАНИЕ" — heading, строка вида "1.1. текст" — clause, остальное — paragraph.
   Списки и таблицы — соответственно list и table.
4. Экран разметки шаблона: слева текст документа блоками, справа панель полей.
   Пользователь выделяет мышкой кусок текста в блоке и нажимает «Сделать полем».
   Появляется диалог: название поля и его источник —
   - реквизит моей организации (выбор из списка моих полей)
   - реквизит клиента (выбор из списка полей клиента)
   - ручной ввод при создании договора (текст, число, дата, сумма)
   - материал из библиотеки

   Список всех полей шаблона виден справа, поле можно снять.
5. Отдельные кнопки «Отметить место для подписи» и «Отметить место для печати» —
   они вставляют в текст плейсхолдеры {{signature}} и {{stamp}}.
6. Сохранение шаблона: исходный файл, структура блоков, список полей.

ВАЖНО: разбор .docx выполняется на сервере в Node.js-окружении
(export const runtime = 'nodejs'), не в Edge.

Результат: я загрузил свой реальный договор, увидел его текст блоками, разметил
в нём реквизиты обеих сторон, дату, сумму и места для подписи и печати. Шаблон сохранён.
```

## Шаг 3 — ЯДРО: генерация .docx по шаблону, без ИИ

```
В рамках того же приложения. Это самый важный этап проекта — не спеши.

Задача: создание договора в режиме strict (строго по шаблону) и скачивание готового .docx.

Сделай:
1. Мастер создания договора в 4 шага с индикатором прогресса:
   Шаг 1 — выбор клиента из списка или создание нового прямо здесь.
   Шаг 2 — выбор режима. Пока активен только «Строго по шаблону», остальные два
   показаны неактивными с подписью «скоро».
   Шаг 3 — выбор шаблона.
   Шаг 4 — форма заполнения: поля, привязанные к реквизитам, подставляются автоматически
   и показаны только для чтения с пометкой откуда взяты; поля ручного ввода — пустые
   для заполнения. Поля с типом «дата» — с календарём, «сумма» — с форматированием.
2. Кнопка «Сгенерировать договор»: на сервере берём исходный .docx шаблона из Storage,
   подставляем значения через docx-templates с полным сохранением оформления оригинала,
   сохраняем результат в бакет contracts.

4. Кнопка «Скачать .docx» отдаёт готовый файл с осмысленным именем вида

ВАЖНО:
- Генерация и рендеринг только в Node.js-окружении (export const runtime = 'nodejs').
- Проверь корректную работу с кириллицей.
- Если плейсхолдер не заполнен — не оставляй {{...}} в готовом файле, подставляй пустую

Результат: я выбрал клиента и шаблон, заполнил пару полей, скачал .docx — открыл его
```

## Шаг 5 — Материалы и подключение Gemini

```
В рамках того же приложения.

Задача: библиотека материалов и два режима генерации с участием ИИ.

Сделай:
1. Миграцию для таблицы materials и приватный бакет materials.
2. Раздел Материалы: добавление материала — название, тип (программа обучения, описание
   услуги, приложение к договору, прочее), содержимое текстом или файлом (.docx, .pdf, .txt),
   теги. Из файлов извлекай текст и сохраняй его вместе с файлом. Список с поиском по
   названию и тегам, просмотр и редактирование.
3. Подключение Google Gemini через @google/genai, ключ — из переменной окружения.
   Модель для правок и разбора — Flash, для генерации с нуля — Pro.
   Все обращения к ИИ идут только с сервера, ключ никогда не попадает в браузер.
4. Активируй режим «Шаблон + правки ИИ» (assisted): после выбора шаблона пользователь
   в свободной форме пишет, что изменить («убери пункт про предоплату», «добавь раздел
   про конфиденциальность», «срок сделай 3 месяца»). ИИ получает структуру блоков шаблона
   и возвращает изменённую структуру в том же формате JSON. Обязательно валидируй ответ:
   если структура невалидна — повтори запрос один раз, потом покажи понятную ошибку.
5. Активируй режим «С нуля» (generative): пользователь выбирает один-два своих договора
   как образец стиля, подключает материалы из библиотеки и описывает, какой договор нужен.
   ИИ строит структуру блоков целиком. Рендеринг — программной сборкой из блоков,
   с настройками оформления по умолчанию: Times New Roman 12, полуторный интервал,
   поля 2 см, отступ первой строки 1.25 см.
6. На шаге 3 мастера добавь выбор материалов, которые надо учесть в договоре.
7. Показывай понятный индикатор во время работы ИИ и корректно обрабатывай таймауты.

ВАЖНО: ИИ работает ТОЛЬКО со структурой блоков в JSON. Он никогда не генерирует файл
и не занимается форматированием. Промпты к модели строй так, чтобы ответ был строго
валидным JSON без пояснений и без markdown-обёртки.

Результат: я создал договор, которого не было в шаблонах, на основе своей программы
обучения из библиотеки материалов — и скачал его в .docx.
```

## Шаг 6 — Блочный редактор и чат с ИИ

```
В рамках того же приложения.

Задача: экран редактирования готового договора.

Сделай:
1. Миграцию для таблицы chat_messages.
2. Экран редактора: на компьютере два столбца — слева документ блоками, справа чат с ИИ.
   На телефоне — переключение вкладками «Документ» и «Правки».
3. Левая часть: блоки списком, каждый кликается и правится как обычный текст.
   У блока при наведении — кнопки: удалить, переместить вверх, переместить вниз,
   добавить блок под ним (с выбором типа). Служебные блоки (реквизиты, подписи)
   не редактируются текстом, а показывают, что именно в них подставится.
   Нумерация пунктов пересчитывается автоматически при добавлении и удалении.
4. Автосохранение изменений с ненавязчивым индикатором «Сохранено».
5. Правая часть: чат. Пользователь пишет просьбу, ИИ получает текущую структуру блоков
   и возвращает изменённую. Изменённые блоки подсвечиваются, вверху появляется панель
   «Принять изменения / Отменить». История сообщений сохраняется и не теряется при
   возврате на экран.
6. Возможность выделить конкретный блок и попросить ИИ изменить только его —
   тогда в модель уходит только этот блок, а не весь документ.
7. Кнопки сверху: «Предпросмотр» (HTML-превью в формате страницы),
   «Скачать .docx», «Сохранить как новую версию».

Результат: я открыл сгенерированный договор, поправил пару пунктов руками, попросил ИИ
переписать раздел об ответственности, принял изменения и скачал итоговый файл.
```
