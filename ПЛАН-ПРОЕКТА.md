# План проекта: приложение для создания договоров

## 1. Суть в двух словах

Веб-приложение, в котором предприниматель или юрист хранит свои шаблоны договоров,
материалы, реквизиты и печати — и собирает готовый .docx-договор с клиентом за пару минут.
Сейчас такой человек копирует старый файл, вручную вычищает чужие реквизиты и следит
за форматированием. Приложение делает это за него, а где нужно — подключает ИИ.
Главное действие: **создать готовый договор с правильным оформлением, реквизитами,
подписью и печатью**. Закрытый сервис по приглашениям, в перспективе — SaaS.

---

## 2. Что умеет

**MVP:**
- Регистрация по коду приглашения и вход по почте с паролем
- Личный кабинет с боковой навигацией, полностью работающий с телефона
- Свои реквизиты и реквизиты клиентов — гибкие, под любую страну
- Загрузка подписей и печатей
- Библиотека шаблонов: загрузка своего .docx и разметка полей подстановки
- Библиотека материалов (программы обучения, описания услуг)
- Клиенты, дела и версии договоров
- Три режима создания: строго по шаблону · шаблон + правки ИИ · с нуля по материалам
- Блочный редактор с чатом ИИ
- Скачивание .docx с печатью и подписью
- Дашборд со сводкой

**Потом:** вход через Google · экспорт в PDF · отправка на почту клиенту ·
электронная подпись · командный доступ · тарифы и оплата · распознавание реквизитов
из скана · сравнение версий · подтверждение почты.

---

## 3. Как этим пользуются

**Главный сценарий:** вход → дашборд → «Создать договор» → выбор клиента → выбор режима →
выбор шаблона и материалов → заполнение полей → генерация → правки в редакторе →
выбор печати и подписи → скачивание .docx → договор лёг в дело клиента.

**Экраны:** вход · регистрация · дашборд · договоры (дела) · страница дела с версиями ·
клиенты · карточка клиента · шаблоны · разметка шаблона · материалы ·
мастер создания договора (4 шага) · редактор договора · настройки (реквизиты,
подписи и печати, профиль).

---

## 4. Что внутри

**Хранит:** пользователей · коды приглашений · свою организацию · гибкие реквизиты ·
подписи и печати · клиентов · шаблоны · материалы · дела · версии договоров ·
переписку с ИИ. Подробная структура — в `CLAUDE.md`, раздел 4.

**Где живут данные:** Supabase — база, вход и хранилище файлов. База нужна однозначно:
разные пользователи, вход в аккаунт, связанные между собой данные, потеря недопустима.

**Внешние сервисы:** Supabase (щедрый бесплатный тариф) · Google Gemini API
(бесплатный лимит у Flash, платный тариф для документов стоит копейки) ·
Vercel для публикации (бесплатного тарифа хватит).

**VPS не нужен.** Ни для ИИ, ни для генерации файлов — всё делает само приложение
на Vercel. Это экономит деньги и время на настройку сервера.

---

## 5. На чём делаем

**Стек:** Next.js + React + TypeScript (и лицо, и кухня в одном проекте) ·
Tailwind CSS · Supabase (база, вход, файлы) · Gemini API · Vercel.
Работа с .docx: `mammoth` для разбора, `docx-templates` для подстановки в готовый шаблон,
`docx` для сборки с нуля.

**Инструмент:** Claude Code в VS Code. Выбран потому, что сборка .docx требует настоящего
Node.js-окружения — это исключает инструменты, работающие только в браузере. Плюс проект
многошаговый, а Claude Code хорошо держит контекст через файл `CLAUDE.md`.

**Предупреждения:**
- ⚠️ Google AI Studio **не выдаёт API-ключи в Беларуси и России**. Ключ создавай,
  находясь в поддерживаемом регионе. Приложение потом работает нормально — запросы идут
  с сервера Vercel в Европе.
- ⚠️ Всё, что касается .docx, должно выполняться в Node-окружении, а не в Edge.
  В коде это `export const runtime = 'nodejs'`. Забудешь — библиотеки не запустятся.
- ⚠️ Печать вставляется по явной метке в шаблоне. Не полагайся на автоматическое
  определение места.

## 6. План по этапам

| Этап | Что делаем | Что работает в конце |
|---|---|---|
| **0** | Каркас, вход по коду приглашения, навигация | Регистрируюсь, вхожу, вижу кабинет |
| **1** | Своя организация, гибкие реквизиты, клиенты, печати | Завёл себя и первого клиента |
| **2** | Загрузка .docx-шаблона и разметка полей | Разметил свой реальный договор |
| **3** | 🔴 **Ядро: генерация .docx по шаблону, без ИИ** | Скачал готовый договор с печатью |
| **4** | Дела, версии, дашборд | Договор в папке клиента, есть «Новая версия» |
| **5** | Материалы + Gemini: режимы assisted и generative | Договор собран по материалам |
| **6** | Блочный редактор и чат с ИИ | Правлю пункты руками и просьбой к ИИ |
| **7** | Стекло, анимации, мобильная полировка | Красиво и удобно везде |

**Почему этап 3 раньше ИИ.** Сборка .docx с сохранением оформления и вставкой печати —
самое рискованное место проекта. Если оно не заработает, ИИ не спасёт: получишь красивый
текст, который нельзя отдать клиенту. Сначала доказываем, что файл собирается идеально
на простой подстановке — потом добавляем интеллект.

**Почему дизайн в конце.** Стекло и анимации накладываются на готовую логику за один-два
подхода. Если делать красоту сразу, каждое изменение функционала будет ломать вёрстку.
При этом адаптивность закладывается с этапа 0 — это структура, а не украшение.

## 9. Советы по работе с Claude Code

- **Держи `CLAUDE.md` в корне и обновляй его.** Claude Code читает его автоматически.
  Когда по ходу дела принимаете новое решение — попроси дописать его в этот файл.
  Так контекст не потеряется через две недели.
- **Коммит после каждого этапа.** Не «в конце дня», а сразу как проверил, что работает.
  Claude Code иногда чинит одно и задевает соседнее — откат должен быть в один шаг.
- **Один промпт = один этап, не больше.** Если хочется впихнуть два — разбей.
  Соблазн «сделай сразу этапы 3 и 4» кончается тем, что не работает ни то, ни другое.
- **Проверяй скачанный .docx в настоящем Word**, а не в предпросмотре браузера или
  в Google Docs. Кириллица, шрифты и позиция печати ведут себя по-разному.
- **Если Claude Code зациклился** — не проси «попробуй ещё раз». Опиши конкретнее, что
  именно не так, или откатись к последнему коммиту и переформулируй задачу мельче.
- **Проси объяснять простыми словами**, что меняется. Это твой проект, и через месяц
  тебе в нём разбираться.
